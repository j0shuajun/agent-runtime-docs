Agent Assets

Agent Runtime의 chat endpoint는 단순 LLM proxy가 아닙니다. 요청마다 사용자 identity, permission group, index 정보를 받아 DeepAgents runtime을 구성하고, 그 안에서 허용된 MCP tool, Skill, Agent만 사용합니다.

Agent Assets는 main agent가 사용할 수 있는 확장 자산입니다. 사용자가 직접 선택하거나 호출하는 대상이 아니라, /v1/chat/completions 요청의 orch metadata와 서비스 설정을 기준으로 runtime이 필요한 자산만 노출합니다.

한눈에 보는 실행 흐름​

Asset 종류​

Asset역할문서
MCP검색, deep search, 외부 tool 실행을 제공하는 server/tool입니다.MCP
Skills특정 작업 방식이나 검토 기준을 담은 instruction bundle입니다.Skills
Agents좁은 검토/분석 작업을 맡는 subagent definition입니다.Agents

Agent가 보는 virtual filesystem​

배포 담당자는 파일을 실제 assets/skills/, assets/agents/에 둡니다. Agent에게는 이 host 경로를 직접 노출하지 않고, 요청의 사용자·권한에 맞춘 virtual root만 보여 줍니다.

Agent-visible path내용권한과 수명
/workspace초안, 중간 분석, main/subagent가 함께 쓸 작업 파일현재 user_id:chat_id thread에서만 read/write/edit. PostgreSQL checkpoint로 이어짐
/memories현재 user_id의 장기 Memory인 /memories/MEMORY.mduser-scoped read-only. 대화 thread가 바뀌어도 같은 사용자에게 이어짐
/skills실제 assets/skills 중 현재 요청에 허용된 Skillread-only
/agents실제 assets/agents 중 현재 요청에 허용된 Agent definitionread-only

예를 들어 user A가 chat 1의 /workspace/notes.md에 쓴 파일은 같은 chat의 다음 요청과 다른 API process에서도 읽을 수 있습니다. 하지만 user A의 chat 2나 user B에게는 보이지 않습니다. Pod의 실제 /, assets/mcp_server.json, 그 밖의 host file은 이 virtual filesystem에 연결하지 않습니다. Shell/execute도 제공하지 않습니다. /memories, /skills, /agents는 read-only이며 Agent가 수정할 수 없습니다.

Agent는 필요할 때 ls, glob, grep, read_file, write_file, edit_file을 사용합니다. Skill 파일을 읽는 경우에는 기존 [Skill] progress가, 그 밖의 filesystem 작업에는 [Tool] <tool> progress가 표시됩니다. Workspace는 내부 작업 공간이므로 Agent가 파일만 쓰고 경로를 알려 주는 것으로 끝내지 않고, 실제 요청 결과를 최종 채팅 본문에 포함해야 합니다.

요청별 context​

chat 요청의 orch metadata는 runtime 내부에서 request-scoped context가 됩니다.

Request-scoped context
{
  "orch": {
    "chat_id": "2b0e1c88-540d-4af7-85d8-b1e7f6fa865e",
    "x_request_id": "896cd7ad-8e3c-4c85-b918-a294d133c44e",
    "identity": {
      "user_id": "employee.one",
      "send_system_name": "ds_assistant"
    },
    "rag_params": {
      "index": "rag-index",
      "permission_groups": ["example-team"]
    }
  }
}
값내부 사용처
user_idsession isolation, usage log, MCP body/header injection
identity.send_system_nameTrusted sender exact passthrough, Sub FE whitelist/base _test, 생략·공백·exact api 개인 경로를 나누는 caller 이름. 미등록 값은 거절됩니다.
chat_id대화 thread, HITL 재개, 중복 요청 판단 범위
x_request_idcaller가 보내는 중복 요청 방지/correlation id. runtime에서는 request_id로 정규화해 MCP/RAG를 추적합니다.
rag_params.indexRAG retrieval index 선택
rag_params.permission_groups인증 후 확정된 MCP server, Skill, Agent visibility와 RAG permission filter

Permission group이 바꾸는 것​

같은 질문이라도 permission_groups가 다르면 runtime이 볼 수 있는 capability가 달라집니다.

대상필터링 방식
MCP serverserver config의 access.permission_groups가 request permission group을 확인합니다.
SkillSKILL.md frontmatter의 access.permission_groups가 적용됩니다.
Agentagent markdown frontmatter의 access.permission_groups가 적용됩니다.
Virtual filesystem허용된 Skill/Agent만 /skills, /agents에 보이고 /workspace는 thread별로 격리됩니다.
RAG retrievalMCP body로 주입된 permission_groups를 RAG filter로 사용합니다.
Runs evidenceLangfuse observation을 main/subagent 중첩 구조로 정리하고 실행 입출력은 자르지 않고 노출하되 고정 내부 설정을 제외합니다. Main system/developer message, Tool description/schema, Tool runtime, framework metadata, provider-private reasoning과 내부 ID는 노출하지 않습니다. Subagent system prompt는 보존합니다.

따라서 권한 그룹을 비워 보내면 검색 결과뿐 아니라 agent가 사용할 수 있는 내부 capability도 줄어들 수 있습니다.

MCP의 requestScopedInjection은 권한 판정과 별개입니다. 요청의 정규화 body field와 inbound header를 source로 사용해 MCP tool argument(body)나 HTTP MCP header(header)로 옮깁니다.

Manifest에 보이는 capability​

GET /v1/manifest는 Router가 RAG service를 이해할 수 있도록 MCP tool, Skill, Agent 목록을 capability로 공개합니다. Manifest는 요청별 permission body가 없는 정적 inventory이므로 access.permission_groups 기준의 사용자별 capability 목록은 /v1/chat/completions runtime에서 결정됩니다.

따라서 restricted Skill/Agent의 이름과 description도 manifest에는 나올 수 있습니다. Manifest는 metadata 보안 경계가 아니므로 asset description에 credential, 사내 민감 정보, 권한으로 숨겨야 할 내용을 넣지 않습니다.

사용자가 지켜야 할 경계​

권장 사항피해야 할 것
orch.identity.user_id, chat_id, x_request_id를 안정적으로 생성합니다.같은 사용자 요청이 아닌데 x_request_id를 재사용하지 않습니다.
caller 유형에 맞는 send_system_name과 Key binding을 사용합니다.Sub FE Key를 개인 user_id에 재사용하지 않습니다.
hitl 종료 상태를 화면에서 추가 질문으로 보여줍니다.HITL이 끝난 chat_id를 버리고 새 대화로 재시작하지 않습니다.
/v1/manifest로 service scope를 이해합니다.MCP tool, Skill file, Agent를 직접 호출하려고 하지 않습니다.
/v1/runs*로 운영 evidence를 확인합니다.provider trace나 숨겨진 reasoning을 API 응답에 기대하지 않습니다.

MCP tool, Skill, main/subagent, model 호출은 Langfuse에 observation으로 기록됩니다. Runs evidence에서 각 observation의 실행 입출력과 이를 감싼 agent node를 함께 보면 어느 agent가 어떤 실행을 했는지 확인할 수 있습니다. Public response는 framework metadata와 내부 ID를 제거하고 소유 관계를 중첩 구조로 직접 표현합니다. Turn Evaluation은 Agent 실행 observation이 아니므로 evidence에 포함하지 않고, Langfuse terminal run.artifact.output.turn_evaluation에만 보존합니다. enabled=false인 MCP는 runtime과 manifest에서 모두 제외되고, includeInManifest=false인 MCP는 chat runtime에서는 쓸 수 있지만 Router manifest에는 보이지 않습니다.
