Quickstart

Agent Runtime에 chat 요청을 한 번 보내서 응답이 오는지 확인하는 문서입니다. 요청 값의 의미나 endpoint별 상세 응답은 Usage Guide와 Endpoints에서 확인해 주세요.

1. Base URL 설정​

Base URL environment
export AGENT_RUNTIME_API_BASE=<agent-runtime-api-base-url>

사용할 model과 index는 catalog에서 먼저 확인합니다.

Catalog requests
curl "$AGENT_RUNTIME_API_BASE/v1/models"
curl "$AGENT_RUNTIME_API_BASE/v1/indices"

2. Chat 요청 보내기​

아래 예제는 non-stream 방식으로 한 번에 JSON 응답을 받습니다.

Chat request
curl "$AGENT_RUNTIME_API_BASE/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<model-id-from-catalog>",
    "stream": false,
    "messages": [
      {"role": "user", "content": "배포 지연의 원인과 권장 조치를 설명해줘"}
    ],
    "orch": {
      "chat_id": "2b0e1c88-540d-4af7-85d8-b1e7f6fa865e",
      "x_request_id": "896cd7ad-8e3c-4c85-b918-a294d133c44e",
      "identity": {
        "user_id": "user-1",
        "send_system_name": "<메모결재 양식에 기입한 시스템명>"
      },
      "rag_params": {
        "index": "rag-index",
        "permission_groups": ["example-team"]
      }
    }
  }'

send_system_name에는 메모결재 양식에 기입한 시스템명을 넣습니다. 시스템 연계를 위해 대량으로 호출하는 경우에만 test를 사용합니다.

최종 문구는 choices[0].message.content에 들어옵니다. finish_reason이 stop이면 답변 완료, hitl이면 추가 질문에 대한 사용자 입력 대기입니다. Non-stream agent 실패는 choices 형식이 아닌 HTTP 500 공통 error envelope로 반환됩니다.
