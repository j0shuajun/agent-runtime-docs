API Key Management

Sub Frontend와 개인 API가 Chat에 사용할 Binding API Key를 발급·Rotation·조회·만료 갱신·폐기하는 내부 운영 API입니다.

위험

이 endpoint에는 별도 application credential이 없습니다. 배포 시 Ingress·network policy에서 /internal/*를 인증된 운영자에게만 노출해야 합니다.

공통 식별자​

특정 Key를 다룰 때 GET은 key_ref query parameter를, PATCH와 DELETE는 {key_ref} path parameter를 사용합니다. 두 위치 모두 다음 두 형식을 받습니다.

UUID key_id
07da0100-661f-405a-be4f-3198a631438e

22자 public_key_id
B9oBAGYvQFq-TzGYpjFDjg

public_key_id는 내부 UUID 16 bytes를 padding 없는 Base64URL로 표현한 공개 식별자이며 비밀값이 아닙니다. 두 형식 모두 canonical round-trip 검사를 통과해야 합니다.

경고

전체 sk-<public_key_id>.<secret> Key는 URL 식별자로 사용할 수 없습니다. Secret이 URL이나 접근 로그에 남지 않도록 422 invalid_key_reference로 거부합니다.

Key 원문은 sk-<22자 public_key_id>.<43자 secret> 형식의 69자입니다. PostgreSQL에는 UUID와 ENCRYPTION_MASTER_KEY에서 전용 HKDF context로 파생한 Key로 계산한 HMAC-SHA256 hash만 저장하며 원문 Key와 secret은 저장하지 않습니다.

1. API Key 발급 및 Rotation​

POST /internal/v1/api-keys
Content-Type: application/json

개인 Key 요청:

{
  "binding_field": "user_id",
  "binding_value": "employee.one",
  "expires_at": "2027-08-20 18:30"
}

Sub Frontend Key는 binding_field="send_system_name", binding_value="medic"처럼 _test가 없는 whitelist base name을 사용합니다.

성공하면 201 Created와 다음 값을 반환합니다.

{
  "key_id": "07da0100-661f-405a-be4f-3198a631438e",
  "public_key_id": "B9oBAGYvQFq-TzGYpjFDjg",
  "api_key": "sk-B9oBAGYvQFq-TzGYpjFDjg.GSaZ5hDpQx2vU8mR1nC7eL4tK9wY6aF3jN0sVbHcXEI",
  "binding_field": "user_id",
  "binding_value": "employee.one",
  "issued_at": "2026-08-20T21:00:00+09:00",
  "expires_at": "2027-08-20T18:30:00+09:00"
}

원문 api_key는 이 응답에서만 한 번 반환됩니다.

발급은 같은 (binding_field, binding_value)의 Key를 교체하는 Rotation입니다. 기존 revoked_at IS NULL 행은 신규 Key의 issued_at으로 폐기되고 신규 Key 하나만 유효합니다. 기존 행은 물리 삭제하지 않습니다.

기존 Key revoked_at = 신규 Key issued_at
신규 Key revoked_at = NULL

폐기와 신규 저장은 하나의 PostgreSQL transaction이며, 신규 저장에 실패하면 기존 Key 폐기도 rollback됩니다. 동일 Binding의 동시 발급도 직렬화되어 최종 active Key는 하나입니다.

2. API Key 조회​

조회는 하나의 GET Endpoint를 사용합니다. key_ref가 없으면 목록, 있으면 단일 Key를 반환합니다.

목록과 Binding 필터​

GET /internal/v1/api-keys
GET /internal/v1/api-keys?binding_field=user_id
GET /internal/v1/api-keys?binding_value=employee.one
GET /internal/v1/api-keys?binding_field=user_id&binding_value=employee.one

key_ref를 보내지 않으면 배열을 반환합니다. binding_field, binding_value는 별도로 또는 함께 사용할 수 있습니다.

[
  {
    "key_id": "07da0100-661f-405a-be4f-3198a631438e",
    "public_key_id": "B9oBAGYvQFq-TzGYpjFDjg",
    "binding_field": "user_id",
    "binding_value": "employee.one",
    "issued_at": "2026-08-20T21:00:00+09:00",
    "expires_at": "2027-08-20T18:30:00+09:00",
    "revoked_at": null,
    "status": "active"
  },
  {
    "key_id": "이전-key-uuid",
    "public_key_id": "이전-public-key-id",
    "binding_field": "user_id",
    "binding_value": "employee.one",
    "issued_at": "2026-07-20T10:00:00+09:00",
    "expires_at": "2027-07-20T10:00:00+09:00",
    "revoked_at": "2026-08-20T21:00:00+09:00",
    "status": "revoked"
  }
]

원문 API Key와 secret_hash는 포함되지 않습니다.

단일 Key 조회​

GET /internal/v1/api-keys?key_ref=07da0100-661f-405a-be4f-3198a631438e
GET /internal/v1/api-keys?key_ref=B9oBAGYvQFq-TzGYpjFDjg

UUID와 Public Key ID 요청은 같은 레코드를 반환합니다.

{
  "key_id": "07da0100-661f-405a-be4f-3198a631438e",
  "public_key_id": "B9oBAGYvQFq-TzGYpjFDjg",
  "binding_field": "user_id",
  "binding_value": "employee.one",
  "issued_at": "2026-08-20T21:00:00+09:00",
  "expires_at": "2027-08-20T18:30:00+09:00",
  "revoked_at": null,
  "status": "active"
}

key_ref와 binding_field 또는 binding_value를 함께 보내면 단일 조회와 목록 필터의 의미가 충돌하므로 422 validation_error로 거부합니다.

3. 만료 시각 갱신​

PATCH /internal/v1/api-keys/07da0100-661f-405a-be4f-3198a631438e
PATCH /internal/v1/api-keys/B9oBAGYvQFq-TzGYpjFDjg
Content-Type: application/json
{
  "expires_at": "2028-08-20 18:30"
}

변경할 수 있는 값은 expires_at뿐이며 응답에는 key_id, public_key_id, Binding, KST timestamp와 계산된 status가 포함됩니다.

4. API Key 폐기​

DELETE /internal/v1/api-keys/07da0100-661f-405a-be4f-3198a631438e
DELETE /internal/v1/api-keys/B9oBAGYvQFq-TzGYpjFDjg

성공하면 204 No Content이며 Body는 없습니다. DB row를 물리 삭제하지 않고 revoked_at에 현재 시각을 기록합니다. API Key 검증 결과는 cache하지 않으므로 다음 Chat 요청부터 401 api_key_revoked가 됩니다.

상태 계산​

api_keys에 status column은 추가하지 않습니다. 조회 시 다음 순서로 계산합니다.

revoked_at != NULL       → revoked
expires_at <= 현재 시각  → expired
그 외                    → active

revoked가 expired보다 우선합니다. 이미 만료됐지만 아직 폐기되지 않은 같은 Binding Key도 Rotation 시 revoked_at을 기록합니다.

시간 입력과 표시​

Timezone이 없는 값은 KST로 해석하고 모든 API 응답은 KST +09:00으로 반환합니다.

2027-08-20
2027-08-20 18:30
2027-08-20T18:30
2027-08-20 18:30:45
2027-08-20T18:30:45.123456
2027-08-20T09:30:00Z
2027-08-20T18:30:00+09:00

PostgreSQL TIMESTAMPTZ는 같은 순간을 저장하므로 DB client session timezone에 따라 화면 offset은 다를 수 있습니다.

대표 오류​

잘못된 UUID, 22자가 아닌 값, 비canonical Base64URL, 전체 sk-... Key는 다음 오류로 거부합니다.

{
  "error": {
    "message": "key_ref must be a canonical UUID or public key ID",
    "type": "invalid_request_error",
    "param": "key_ref",
    "code": "invalid_key_reference"
  }
}

HTTP status는 422 Unprocessable Entity입니다. 정상 형식이지만 DB에 없는 식별자는 404 api_key_not_found입니다.

기존 artk_<UUID>.<secret> 문자열은 발급하거나 Chat 인증에 허용하지 않습니다. 해당 형식의 secret은 DB에서 복원할 수 없으므로 새 Key를 발급해 caller 설정을 교체해야 합니다.
