Search

Search Proxy는 RAG API를 Agent Runtime API 경계로 한 번 감싼 endpoint입니다. RAG API를 사용자 서비스에서 직접 호출하게 하지 않고, RAG index allowlist, query normalization과 request id 생성을 거친 뒤 RAG API로 전달합니다.

정보

일반 사용자 화면은 Search Proxy를 직접 호출하지 않아도 됩니다. 대부분의 검색은 chat runtime의 MCP tool이 수행하고, Search Proxy는 내부 검색 도구나 운영 검증용으로 사용합니다.

공통 payload​

Request body
{
  "index_name": "rag-index",
  "query_text": "deployment delay root cause",
  "permission_groups": ["example-team"],
  "num_result_doc": 5,
  "fields_exclude": ["v_merge_content_title"]
}
필드의미
index_name하나 이상의 RAG index. 여러 index는 comma-separated string으로 전달합니다. 빈 문자열, wildcard, allowlist 밖의 값은 422로 거절됩니다.
query_text검색 query. query-term 외 endpoint는 제어문자/특수문자가 검색 가능한 text로 정리됩니다.
permission_groupsRAG backend가 접근 권한 필터에 사용하는 그룹입니다.
num_result_doc반환할 결과 수입니다. 기본값은 30입니다. RAG 계약에 맞게 1부터 50까지를 사용하는 것을 권장하며, RAG Proxy 자체가 이 범위를 자르지는 않습니다.
fields_excludeRAG 응답에서 제외할 field 목록입니다. 기본값은 ["v_merge_content_title"]입니다.

응답에는 서버가 만든 X-Request-Id header가 포함됩니다. RAG backend가 성공하면 backend의 body와 content type을 그대로 반환합니다. 즉 응답 body의 세부 구조는 RAG API 계약을 따르고, RAG API는 호출 전 검증과 운영 로그 경계를 담당합니다. Search는 Chat 전용 usage ledger에 행을 만들지 않으며, response의 X-Request-Id와 application log/trace로 관측합니다.

Request schema는 알 수 없는 추가 field를 거절합니다. KNN/RRF/CC의 filter는 value가 모두 list인 object여야 하고, query-match의 operator는 대문자 OR 또는 AND만 허용합니다. Upstream이 오류를 반환하면 private body를 그대로 전달하지 않고, 같은 HTTP status와 safe common error envelope, X-Request-Id를 반환합니다.

Search endpoint별 용도​

Endpoint추가 필드용도
POST /v1/search/retrieve-bm25-keyword가 중요하고 exact term matching이 유리할 때
POST /v1/search/retrieve-knnfiltersemantic/vector 검색이 필요할 때
POST /v1/search/retrieve-rrffilterBM25와 vector 결과를 rank fusion으로 함께 사용할 때
POST /v1/search/retrieve-ccfilter, bm25_boost, knn_boostRAG의 기본 hybrid retrieval 경로
POST /v1/search/query-matchfield, operatorBM25 기반으로 특정 field에서 token match를 하고 싶을 때
POST /v1/search/query-termfield특정 field에 exact match 기반 term query를 보낼 때

Hybrid retrieval 예시​

Request
curl "$AGENT_RUNTIME_API_BASE/v1/search/retrieve-cc" \
  -H "Content-Type: application/json" \
  -d '{
    "index_name": "rag-index",
    "query_text": "deployment delay remediation",
    "permission_groups": ["example-team"],
    "num_result_doc": 5,
    "filter": {},
    "bm25_boost": 0.02531451142318286,
    "knn_boost": 7.980074401837717
  }'

Field match 예시​

Request
curl "$AGENT_RUNTIME_API_BASE/v1/search/query-match" \
  -H "Content-Type: application/json" \
  -d '{
    "index_name": "rag-index",
    "query_text": "deployment delay",
    "permission_groups": ["example-team"],
    "num_result_doc": 5,
    "field": "title",
    "operator": "AND"
  }'
