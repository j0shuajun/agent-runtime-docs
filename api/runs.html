Runs

Evidence는 실행 결과를 자르지 않지만, 고정된 내부 설정은 공개 응답에서 제외합니다.

Runs API는 사용자에게 답변 전문을 다시 보여주는 API가 아닙니다. 운영자와 디버깅 도구가 run 상태, loop telemetry, main/subagent 실행 구조, 정확한 observation 입출력을 확인하기 위한 조회 API입니다.

팁

사용자 문의를 디버깅할 때는 먼저 POST /v1/runs로 run_id를 찾고, 그 다음 detail과 evidence를 조회합니다. request_id를 알고 있다면 usage log에서 먼저 필터링한 뒤 run summary를 확인해도 좋습니다.

POST /v1/runs​

특정 user_id의 run summary를 KST 시간 범위와 cursor 기준으로 페이지 단위 조회합니다. 답변 전문, provider trace, 검색 결과 본문은 목록 응답에 들어가지 않습니다.

필드의미
user_id조회할 사용자 id입니다. 필수입니다. 이 사용자의 run 안에서 최신순으로 limit개를 가져옵니다.
from조회 시작 시각입니다. YYYY-MM-DD, 분/초를 포함한 datetime, ISO T·Z·UTC offset 형식을 허용합니다. Timezone이 없으면 KST로 해석합니다.
to조회 종료 시각입니다. from과 같은 형식을 사용하며, 명시적 offset은 그 값을 존중합니다.
limit한 번에 받을 run 개수입니다. 1부터 100까지 허용되고 기본값은 20입니다.
cursor다음 페이지 조회용 문자열입니다. 서버가 준 값을 그대로 다시 보내야 합니다.
Request
curl "$AGENT_RUNTIME_API_BASE/v1/runs" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "employee.one",
    "from": "2026-07-14",
    "to": "2026-07-15",
    "limit": 20
  }'
Response
{
  "items": [
    {
      "run_id": "run_01J00000000000000000000000",
      "user_id": "employee.one",
      "chat_id": "2b0e1c88-540d-4af7-85d8-b1e7f6fa865e",
      "request_id": "896cd7ad-8e3c-4c85-b918-a294d133c44e",
      "created_at": "2026-07-14T10:12:00+09:00",
      "status": "completed",
      "model": "<model-id-from-catalog>",
      "stream": true,
      "interaction_id": null,
      "parent_run_id": null,
      "phase_index": 0
    }
  ],
  "query": {"user_id": "employee.one", "from": "2026-07-14", "to": "2026-07-15"},
  "page": {"limit": 20, "returned": 1, "has_more": false, "next_cursor": null}
}

/v1/runs는 전체 run 중 최근 N개를 먼저 뽑고 그 안에서 user_id를 거르는 API가 아닙니다. DB query 단계에서 user_id를 먼저 적용한 뒤, 그 사용자의 run을 created_at DESC, run_id DESC로 정렬해 limit개를 반환합니다.

HITL 관계 필드는 기존 목록 field 뒤에 추가됩니다.

필드의미
interaction_id일반 non-HITL run은 null입니다. HITL이 실제로 발생한 최초 phase는 자신의 run_id, resume phase는 최초 HITL run의 id입니다.
parent_run_id최초 phase는 null, resume phase는 직전 phase의 run_id입니다.
phase_index최초 phase는 0, resume할 때마다 1씩 증가합니다.

from과 to는 KST 기준입니다. from: "2026-07-14"는 2026년 7월 14일 00:00 KST부터, to: "2026-07-15"는 2026년 7월 15일 하루가 끝나는 범위까지를 의미합니다. to: "2026-07-14 10:30"처럼 분 단위로 지정하면 그 분까지 포함되도록 조회합니다.

Cursor로 다음 페이지 조회​

첫 응답에서 page.has_more가 true이면 page.next_cursor가 함께 내려옵니다. 다음 페이지를 받을 때는 user_id, from, to, limit을 그대로 두고 cursor만 추가합니다.

    "limit": 2,
    "returned": 2,
    "has_more": true,

    "user_id": "employee.one",
    "from": "2026-07-14",
    "to": "2026-07-15",

}
경고

cursor는 사람이 해석하거나 수정하는 값이 아닙니다. limit, user_id, from, to 중 하나라도 바꾸면서 이전 cursor를 재사용하면 422로 거절됩니다. 조건을 바꿔 조회하려면 cursor 없이 첫 페이지부터 다시 요청합니다.

GET /v1/runs/{run_id}​

하나의 run summary, loop telemetry, main/subagent 실행 트리를 조회합니다.

Request
curl "$AGENT_RUNTIME_API_BASE/v1/runs/run_01J00000000000000000000000"
Response
{
  "run": {
    "chat_id": "2b0e1c88-540d-4af7-85d8-b1e7f6fa865e",
    "request_id": "896cd7ad-8e3c-4c85-b918-a294d133c44e",
    "created_at": "2026-07-14T10:12:00+09:00",
    "status": "completed",
    "model": "<model-id-from-catalog>",
    "stream": true,
    "interaction_id": null,
    "parent_run_id": null,
    "phase_index": 0
  },
  "loop": {
    "tool_calls": 2,
    "model_calls": 3,
    "stop_reason": "completed",
    "duration_ms": 12400,
    "repeats_blocked": 0,
    "compaction": {
      "occurred": true,
      "count": 1,
      "cutoff_index": 37
    }
  },
  "execution_summary": [
    {
      "type": "agent",
      "name": "main",
      "observations": [
        {"type": "model", "name": "main"},
        {"type": "tool", "name": "rag_search"},
        {"type": "skill", "name": "policy-research"},
        {
          "type": "agent",
          "name": "researcher",
          "observations": [
            {"type": "model", "name": "researcher"},
            {"type": "tool", "name": "deep_search"},
            {"type": "model", "name": "researcher"}
          ]
        },
        {"type": "model", "name": "main"}
      ]
    }
  ],
  "links": {
    "self": "/v1/runs/run_01J00000000000000000000000",
    "evidence": "/v1/runs/run_01J00000000000000000000000/evidence"
  }
}

Run detail의 run은 PostgreSQL summary에서, loop는 해당 run_id의 Langfuse run.artifact에서, execution_summary는 Langfuse semantic observation에서 읽습니다. Public projection은 user_id나 실제 model/tool 입출력을 포함하지 않습니다. 사용자별 discovery가 필요하면 PostgreSQL-backed POST /v1/runs list에서 user_id로 먼저 조회한 뒤 선택한 run_id로 detail/evidence를 조회합니다.

이 응답은 개괄용입니다. execution_summary의 첫 node는 main agent이고, 그 안의 observations는 실제 실행 순서입니다. 같은 tool을 glob → ls → glob 순서로 호출하면 세 항목도 그 순서로 그대로 나타납니다. Subagent 호출은 실행 위치에 중첩된 type="agent" node 하나로 표현되므로 같은 이름의 subagent를 여러 번 호출해도 배열 안의 서로 다른 node로 구분됩니다. 실제 input/output은 evidence에서 확인합니다.

위치해석
run.statusrun의 최종 상태입니다. Detail에서는 completed, hitl, failed 중 하나입니다. running은 list에서만 보이며 detail은 아직 열리지 않습니다.
loop.tool_callsagent가 실행한 tool call 수입니다. 검색이나 MCP 호출이 많았는지 볼 때 사용합니다.
loop.model_callsmodel 호출 수입니다. continuation이나 재시도가 많으면 커질 수 있습니다.
loop.repeats_blocked같은 tool call 반복이 차단된 횟수입니다.
loop.compaction이번 요청 중 role-aware rolling compaction이 관측됐는지 보여줍니다. Snapshot text, raw offload path, raw history content는 포함하지 않습니다.
execution_summarymain/subagent 소유 구조와 model·tool·skill의 실제 실행 순서를 보여줍니다. 입력과 출력은 포함하지 않습니다.

Runs list와 evidence endpoint에는 loop가 없습니다. Compaction metadata는 Chat terminal, non-stream response와 Runs detail에만 포함됩니다.

Compaction 구현이 role-aware snapshot으로 바뀌어도 run.artifact.output.loop의 공개 shape와 Langfuse observation 기록 방식은 바뀌지 않습니다. Oversized input 거절도 같은 loop object에서 stop_reason=context_input_too_large로만 구분합니다.

loop.tool_calls는 framework raw counter이므로 subagent task와 Skill read_file도 포함할 수 있습니다. execution_summary는 이들을 각각 agent, skill로 읽기 쉽게 표현하므로 단순히 type="tool" 항목 수와 비교하면 숫자가 같지 않을 수 있습니다.

이행기에 생성된 run.artifact에는 loop.compaction이 없을 수 있습니다. Runs detail은 그 경우에만 {"occurred": false, "count": 0, "cutoff_index": null}을 보정합니다. 이미 compaction 키가 있는데 count가 빠졌거나 summary_text, file_path 같은 private field가 들어 있으면 public projection은 실패합니다.

GET /v1/runs/{run_id}/evidence​

Langfuse에 남은 main/subagent, model, tool, skill 등의 semantic observation을 조회합니다. 실행 중인 run의 evidence를 미리 조회하는 API는 아닙니다.

Request
curl "$AGENT_RUNTIME_API_BASE/v1/runs/run_01J00000000000000000000000/evidence"
Response
{
  "run_id": "run_01J00000000000000000000000",
  "observations": [
    {
      "type": "agent",
      "name": "main",
      "observations": [
        {
          "type": "model",
          "name": "main",
          "input": {"messages": [{"role": "user", "content": "배포 지연을 조사해줘"}]}
        },
        {
          "type": "tool",
          "name": "rag_search",
          "input": {"query": "deployment delay 원인"},
          "output": {"results": [{"title": "Deployment Delay Overview", "score": 0.82}]}
        },
        {
          "type": "agent",
          "name": "researcher",
          "observations": [
            {
              "type": "model",
              "name": "researcher",
              "input": {"messages": [{"role": "system", "content": "독립적으로 원인을 검토한다."}]}
            },
            {
              "type": "tool",
              "name": "deep_search",
              "input": {"query": "deployment delay verification"},
              "output": {"results": [{"title": "Verification", "score": 0.91}]}
            },
            {
              "type": "model",
              "name": "researcher",
              "output": "조사 결과입니다."
            }
          ]
        },
        {
          "type": "model",
          "name": "main",
          "output": "최종 답변입니다."
        }
      ]
    }
  ],
  "page": {"returned": 8, "complete": true, "next_cursor": null},
  "links": {
    "self": "/v1/runs/run_01J00000000000000000000000/evidence",
    "run": "/v1/runs/run_01J00000000000000000000000",
    "next": null
  }
}
위치해석
observations[]main agent를 root로 하는 실행 트리입니다. Agent의 observations 안에 자신이 소유한 실행과 subagent가 실제 순서대로 들어갑니다.
type="model" / nameLLM 호출 한 번과 그 호출을 소유한 Agent 이름입니다. name은 provider model ID가 아닙니다.
input / output실행 결과를 preview로 자르거나 다시 요약하지 않은 sanitized JSON-safe 값입니다. 아래에 명시한 고정 내부 설정만 제외하며, 결과를 보려고 observation별 detail API를 다시 호출할 필요가 없습니다.
error실패한 observation에만 { "message": "..." } 형태로 붙습니다. 성공한 항목에는 상태 필드를 반복하지 않습니다.
page현재 응답의 observation 수, 전체 완료 여부, 다음 cursor를 보여줍니다.

Evidence는 query option 대신 JSON byte budget으로 자동 pagination합니다. 한 page의 soft budget은 4 MiB이며 observation 하나를 중간에서 자르지 않습니다. 다음 observation을 넣으면 budget을 넘는 경우 page.complete=false, page.next_cursor, links.next가 내려옵니다. Client는 links.next를 그대로 호출하면 됩니다. 다음 page에도 구조를 이해하는 데 필요한 agent ancestor는 반복되지만 page.returned는 이번 page에서 새로 반환한 observation 수만 셉니다. 한 observation이 8 MiB를 넘으면 원본을 자르지 않고 413 observation_too_large를 반환합니다. 큰 JSON은 HTTP gzip으로 전송할 수 있습니다.

조회 가능 시점과 오류​

상황Detail / evidence 응답의미
PostgreSQL에 run_id가 없음404 run not found해당 run이 없습니다.
Summary status가 running409 run_not_terminal아직 결과 artifact를 조회할 수 없습니다.
Terminal이지만 artifact가 아직 보이지 않음설정된 read deadline 안에서 재조회 후 503 observability unavailableLangfuse 반영 지연 또는 write 실패입니다.
Terminal summary와 artifact가 모두 준비됨200Detail/evidence를 읽을 수 있습니다.

Langfuse Sessions에서는 HTTP 요청 하나가 LangGraph trace 하나가 됩니다. HITL turn은 질문 요청과 각 resume 요청이 서로 다른 run_id trace로 보입니다. 각 trace에는 해당 HTTP 요청의 run.artifact child 하나가 남고, run 관계는 interaction_id, parent_run_id, phase_index로 연결됩니다. 다중 turn session은 기존처럼 오래된 turn이 위, 최신 turn이 아래에 보입니다. 재조회 시간은 LANGFUSE_RUN_READ_TIMEOUT의 전체 deadline을 따르므로 evidence가 큰 run도 고정된 몇 번의 시도만으로 조기에 실패하지 않습니다.
