MCP

MCP server는 assets/mcp_server.json 또는 기본 설정에서 로드됩니다. Non-empty mcpServers asset config가 있으면 그 파일을 우선 사용하고, 파일이 없거나 server 목록이 비어 있으면 built-in retriever, ds_retriever 구성을 사용합니다.

사용자는 MCP tool을 직접 호출하지 않습니다. Chat 요청에 올바른 orch metadata를 전달하면 runtime이 권한과 설정을 기준으로 사용할 수 있는 MCP tool만 agent에게 노출합니다.

기본 MCP server​

Server대표 tool용도
retrievermcp__retriever__rag_searchRAG index에서 일반 retrieval을 수행합니다.
retrievermcp__retriever__deep_searchRAG 질문에 대해 더 깊은 검색 전략을 수행합니다.
ds_retrievermcp__ds_retriever__ds_rag_searchDS index 쪽 retrieval을 수행합니다. 현재 asset은 includeInManifest=false이므로 Chat에서는 쓸 수 있어도 Manifest에는 보이지 않습니다.

runtime은 tool 이름을 mcp__<server_name>__<tool_name> 형태의 canonical name으로 관리합니다.

기본 server 구현은 server별 디렉터리와 공용 helper 디렉터리로 나뉩니다.

Bundled MCP server layout
app/mcp_servers/
  _common/
    retriever.py
    search_strategy.py
  retriever/
    server.py
    deep_search.py
  ds_retriever/
    server.py

_common/은 RAG/DS retriever가 함께 쓰는 RAG gateway, rerank, result-size policy, strategy 설명을 담습니다. deep_search는 RAG retriever 전용 pipeline이므로 retriever/deep_search.py에 있습니다.

MCP config 예시​

MCP config
{
  "mcpServers": {
    "retriever": {
      "transport": "stdio",
      "command": "python",
      "args": ["-m", "app.mcp_servers.retriever.server"],
      "env": {
        "RAG_API_URL": "${RAG_API_URL}",
        "RAG_API_KEY": "${RAG_API_KEY}",
        "RAG_X_DEP_TICKET": "${RAG_X_DEP_TICKET}",
        "INDEX": "${RAG_INDEX}"
      },
      "requestScopedInjection": {
        "body": [
          {"from": "permission_groups", "to": "permission_groups"},
          {"from": "index", "to": "index", "overwrite": false},
          {"from": "chat_id", "to": "chat_id"},
          {"from": "request_id", "to": "request_id"},
          {"from": "user_id", "to": "user_id"}
        ]
      },
      "enabled": true,
      "includeInManifest": true
    }
  }
}

MCP access​

MCP server entry의 access.permission_groups는 이 server의 tool을 어떤 요청에 노출할지 정하는 allowlist입니다. access가 없거나 permission_groups가 비어 있으면 public MCP이고, 값이 있으면 chat request의 orch.rag_params.permission_groups와 하나라도 겹칠 때만 runtime이 해당 MCP server를 로드합니다.

이 값은 MCP endpoint로 전달되는 payload가 아닙니다. Runtime이 graph를 만들기 전에 visible MCP server를 줄이는 app-owned metadata입니다. 권한이 없는 요청에서는 tool 목록에 들어가지 않고, canonical tool name을 알고 호출하더라도 tool policy에서 거부됩니다.

설정역할예시
enabledMCP server를 runtime에서 완전히 켜거나 끕니다. 기본값은 true입니다.특정 MCP를 임시로 끌 때 false
includeInManifest실행은 유지하되 Router manifest capability에 보일지 정합니다.내부 전용 MCP는 false
access.permission_groups권한 제어가 필요할 때 씁니다. MCP server/tool visibility를 제한합니다.restricted-team 권한 사용자에게만 선택적 MCP 노출
requestScopedInjectionMCP server에 전달해야 하는 request field가 있을 때 씁니다. body는 tool argument를, header는 HTTP MCP header를 채웁니다.retriever argument에 ACL을 넣거나 HTTP MCP header에 correlation id 전달
timeout이 MCP server의 tool call을 기다리는 시간입니다. stdio MCP는 host wrapper가 적용하고, HTTP/streamable MCP는 adapter connection timeout으로도 전달됩니다. 미지정 시 내부 기본 60초이며, 기본 asset도 각 MCP에 60초를 명시합니다.MCP별 정상 실행 시간이 긴 서버만 개별 상향
sse_read_timeoutstreamable/SSE MCP 연결이 열린 뒤 다음 이벤트가 오래 없을 때의 read timeout입니다. 미지정 시 adapter 기본 300초를 씁니다.기본값과 다른 event read 상한이 필요한 서버

enabled=false와 includeInManifest=false는 다릅니다. enabled=false는 server를 runtime config에서 제외하므로 chat과 manifest 모두에서 사라집니다. includeInManifest=false는 chat runtime에서는 사용 가능하지만 /v1/manifest의 capability inventory에서만 숨깁니다.

timeout은 transport별로 적용 방식이 다릅니다. stdio MCP에서는 SDK connection 인자로 넘기지 않고 RAG API가 tool 실행을 감싸는 상한으로 사용합니다. HTTP/streamable MCP에서는 adapter connection timeout으로도 전달하고, 같은 값으로 tool 실행도 감쌉니다. 이 값과 별도로 RAG API는 MCP_DISCOVERY_TIMEOUT으로 server별 tool discovery 전체를 감쌉니다. Manifest는 server별 best-effort 방식이라 느리거나 실패한 MCP만 빠진 partial inventory를 반환할 수 있습니다. 반면 Chat graph compile은 현재 요청에 visible한 enabled MCP 세트의 완전성을 요구합니다. 하나라도 discovery가 실패하면 partial tool set으로 실행하지 않고 503 mcp_discovery_failed로 거절합니다.

stdio MCP의 command가 python 또는 python3이면 runtime에서 현재 RAG API process의 Python executable로 바꿔 실행합니다. .venv로 API를 띄운 local E2E에서는 child MCP도 같은 .venv를 사용합니다. 절대 경로나 별도 launcher처럼 명시적인 custom command는 그대로 전달됩니다.

sse_read_timeout은 tool 실행 전체 시간이 아니라, streamable/SSE 연결이 열린 뒤 다음 event가 오지 않는 시간을 얼마나 기다릴지 정하는 값입니다. 기본 asset은 adapter 기본 300초를 사용하므로 별도로 명시하지 않습니다.

Request-scoped injection​

agent가 MCP tool을 부를 때 요청 context를 MCP tool argument 또는 HTTP header에 주입할 수 있습니다. requestScopedInjection은 배열이 아닌 object이며 destination인 body와 header를 명시합니다. source인 from은 RAG chat body의 정규화 field와 inbound HTTP header를 함께 검색하므로 body→body, header→body, body→header, header→header를 모두 표현할 수 있습니다. header destination은 HTTP/SSE 계열 MCP에서만 사용할 수 있고 stdio/websocket에서는 설정 오류로 거부됩니다.

Injection source일반적인 target의미
permission_groupspermission_groupsRAG backend 권한 필터
indexindex검색 대상 index
request_idrequest_iddownstream correlation
user_iduser_id사용자 기준 logging 또는 filtering

overwrite: false를 두면 destination에 이미 있는 tool argument나 static HTTP header를 보존합니다. index처럼 agent가 의도적으로 좁힌 값을 유지하거나 고정 인증 header를 지켜야 할 때 사용합니다. HTTP header 이름 비교는 대소문자를 구분하지 않습니다.

경고

같은 source 이름이 정규화된 body와 inbound header에 둘 다 있으면 서버는 우선순위를 임의로 고르지 않고 오류로 거절합니다. 예를 들어 from: user_id를 쓰면 같은 이름의 inbound header를 함께 보내지 않습니다. HTTP header destination은 scalar만 허용하므로 list인 permission_groups는 body destination에 넣고, header에는 user_id, chat_id, request_id, model처럼 scalar source만 사용합니다.

Evidence observation​

MCP tool을 evidence용으로 따로 선택하는 설정은 없습니다. 실행된 MCP tool은 Langfuse에 semantic tool observation으로 기록되고, Runs evidence API에서 JSON-safe input/output, status, error, 소유 agent를 함께 조회할 수 있습니다.

Evidence request
curl "$AGENT_RUNTIME_API_BASE/v1/runs/run_01J00000000000000000000000/evidence"

어느 agent가 tool을 실행했는지는 semantic_parent_observation_id로 확인합니다. parent_observation_id는 Langfuse native parent를 그대로 보존하므로 응답에 없는 framework span을 가리킬 수 있습니다. Public execution tree는 semantic parent를 기준으로 읽습니다.
