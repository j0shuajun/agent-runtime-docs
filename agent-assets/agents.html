Agents

Agent는 특정 검토나 분석을 맡는 subagent definition입니다. 사용자는 Agent를 직접 선택하지 않습니다. Main agent가 task prompt만으로 끝낼 수 있는 독립 조사, 좁은 검토, 초안 점검에 사용합니다.

파일 구조​

Agent directory
assets/
  agents/
    process-reviewer.md

위 경로는 배포 담당자가 관리하는 실제 asset 위치입니다. Runtime에서는 현재 요청에 허용된 definition만 Agent-visible /agents/<name>.md에 read-only로 연결합니다. Agent가 이 파일을 읽을 수 있다는 사실과 실제 subagent를 실행할 수 있다는 사실은 구분됩니다. 실행 후보와 tool은 계속 runtime control plane이 구성하며, markdown을 workspace에 복사해 기능을 활성화하지 않습니다.

Agent definition
---
name: process-reviewer
description: Review process-engineering answers for missing assumptions and caveats.
skills:
  - evidence-review
tools:
  - mcp__retriever__rag_search
access:
  permission_groups:
    - ORG_PROCESS
---

You are a focused process-engineering reviewer.
Check whether the draft answer names the relevant process, mechanism, and evidence gap.
Return concise private guidance to the main agent.

ORG_PROCESS는 frontmatter 형식을 보여 주기 위한 예시입니다. 실제 Agent에는 운영 권한 정책에서 정한 그룹명을 사용합니다.

필드 기준​

필드의미
name생략하면 Markdown 파일명의 stem을 사용하는 subagent 이름입니다.
description필수입니다. Main agent와 /v1/manifest가 agent를 이해할 때 사용합니다.
skills비어 있지 않으면 이 subagent에 permission-filtered /skills native source를 열어 줍니다. 현재는 적힌 이름별 preload·allowlist가 아닙니다.
toolstool registry에 실제로 있는 canonical name만 이 subagent에 전달됩니다. 알 수 없는 이름은 제외되고 ask_user는 선언해도 subagent에 주지 않습니다.
accesspermission group 기준으로 Agent 노출 범위를 제한합니다.
본문subagent system prompt입니다.

runtime은 asset-defined agent 외에도 general-purpose subagent를 함께 구성합니다. 다만 HITL tool인 ask_user는 subagent에게 직접 노출하지 않습니다. 사용자에게 추가 질문을 보낼지에 대한 결정은 main agent가 처리합니다.

general-purpose는 runtime이 합성하는 helper이고 assets/agents/*.md inventory가 아닙니다. 따라서 asset-defined Agent가 없으면 /v1/manifest 응답의 capabilities.agents가 빈 배열이어도 general-purpose 위임은 동작할 수 있습니다.
