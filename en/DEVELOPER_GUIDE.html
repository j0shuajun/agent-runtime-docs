Developer Guide

This guide covers runtime configuration, streaming, observability, PostgreSQL, MCP, and assets for developers/operators. See Usage guide for caller request rules.

Runtime env​

Startup validates required and conditional settings. Changes require restart. New booleans accept trimmed, case-insensitive true/false only; unset uses the default, while blank/other values are errors. Feature OFF differs from a configured dependency failure.

warning

Any configured Langfuse, Rerank, or Internal LLM value, including only a ticket, requires its complete three-value group. Personalization defaults to ON and requires all three Internal LLM values. Explicitly set PERSONALIZATION_ENABLED=false before leaving that group empty.

Turn Evaluation replaces the former Continuation Gate retry budget. complete permits Memory/summary postprocessing; needs_revision returns to the compiled Main model within the revision budget. Initial and revised answers stream immediately. Processing progress appears only before an actual revision and is hidden with details OFF. One Main invocation's chunks concatenate unchanged; distinct valid blocks receive the needed blank line consistently in SSE, terminal, non-stream, and storage. Internal evaluation instructions never enter the user answer.

Evaluation uses a fixed 30-second overall budget for initial request, JSON/schema validation, optional repair, and automatic Memory planning, independently of LLM_TIMEOUT. Timeout, Internal LLM failure, or critical schema failure preserves the latest Main answer and skips revision/persistence. Memory and conversation-summary decisions validate independently: one invalid side effect does not discard a valid completion/revision decision.

Without compaction, the evaluator reads the current turn's raw user/model/tool/final execution. With compaction, it reads the effective summary projection plus raw execution after the cutoff, without reinjecting large pre-compaction results. Summary may support completion/conversation summary, but is not direct evidence for new Memory facts.

Compaction policy​

DeepAgents 0.7.15 native SummarizationMiddleware compacts long context. Raw messages remain canonical checkpoint history. Messages before _summarization_event.cutoff_index project as a summary HumanMessage(lc_source="summarization"); recent tail stays raw. Native partitioning preserves the latest user input and unfinished Tool/HITL protocol.

There is no compaction environment knob. Catalog max_input_tokens declares gateway input capacity and maps directly to the identically named LangChain profile. DeepAgents uses its native 85% trigger and 10% keep window. Provider max_tokens is an output-generation parameter, unrelated to input capability.

Summary input is bounded to 4K tokens. Native selection uses last, start_on=human, and partial/system inclusion. Only if that returns empty is the start_on constraint removed with the same budget/direction to permit tool tails. Selection errors propagate as context_compaction_failed, not empty success. Small thresholds belong only in test-owned fixtures, never production configuration.

The event stores cutoff, summary message, and archive path; it does not physically replace raw checkpoint messages. Model input becomes:

Native effective context
single system

→ recent tail after cutoff

Raw compacted history is archived privately under /runtime/conversation_history/**. The summary points to that archive. If both primary/fallback selections are empty, no fake summary is created. Successful archive storage permits archive-only continuation with recent tail and targeted grep/offset-limited read_file recovery. The full archive is not injected by default; storage failure does not record a successful event/cutoff.

The summary invocation is named compaction and uses the Main model. Native usage checks the latest effective AIMessage; fresh post-compaction usage can trigger again even with a small approximate count. Empty model summaries and provider/ selection failures terminate explicitly as context_compaction_failed.

Large tool results use native offload to /runtime/large_tool_results/<tool-call-id> with a bounded preview and recovery path. grep and limited reads recover needed details. Runtime artifacts do not consume workspace quota; models cannot write/edit them. Retriever/Deep Search use the same native policy without an additional character limit.

Streaming announces compaction. Completed cycles rearm only after actual Main content/tool/Skill/Agent work; summarizer activity, empty model events, and heartbeat do not rearm. Summary token streams remain private, and non-stream/artifact structure is unchanged.

Large routed history is deduplicated against the checkpoint and appended as a new suffix rather than rejected merely at the trigger. Failed-request retries do not append already-checkpointed user messages. Checkpoint read failure is explicit, never treated as empty history. Overflow remaining after forced compaction has finish_reason=error, loop.stop_reason=context_overflow; oversized latest user input must be split. Summary failures use context_compaction_failed.

System prompt and Harness Profile​

Service identity, search policy, and filesystem rules remain in configs/system_prompt.jinja2. Harness Profile is an official middleware extension point, not a second hardcoded prompt policy.

A caller's single system text stays request-local configurable data. Main middleware appends an authority wrapper and a JSON-string serialized instruction after the service runtime context. Serialization separates structure from caller text; it does not erase instruction meaning. Subagents do not include this middleware, and Evaluator/compactor use separate internal boundaries. Nothing persists into messages/checkpoints or silently carries into later requests/resumes.

Runtime resolves the Main/subagent model profile, excludes default native summarization, and explicitly installs configured graph middleware. It does not temporarily mutate a library-global factory during concurrent compilation.

Why can requests end around 300 seconds before LLM_TIMEOUT?​

Ingress, API gateway, or load-balancer read/idle timeout may expire first. The application setting cannot extend those policies. 300 seconds is not a fixed repository default; check annotations, controller ConfigMaps, and gateway policies.

Outbound SEND_SYSTEM_NAME is distinct from inbound trusted sender matching. Caller Auth verifies API Keys/bindings; Permission independently looks up user groups. Authentication OFF still uses a configured Permission URL; an empty URL uses request groups. Exact trusted senders with authentication ON retain their bypass of both checks. Personalization OFF selects a Jinja explanation and blocks ordinary Memory file reads without deleting records. Completion and conversation summary continue under existing Internal LLM conditions; Memory decisions alone are skipped.

Main-only update_user_memory accepts add/update intentions rather than a rewritten Markdown document; semantic targets, dates, and atomic editing are handled by the shared Memory planner. It requires personalization ON. delete_user_memory remains available ON/OFF: clear needs no Internal LLM, while partial requires its configured connection. Whole-item deletion removes its date; phrase deletion preserves the remaining item's date. A missing target or real ambiguity does not trigger approximate deletion or an invented add. Updates return updated/unchanged/conflict/failed; delete conflicts reread/replan until success. Automatic edit proposals use the same path, skip stale versions, exclude turn-local deletion targets, and may retain unrelated facts. No additional environment settings are needed.

One encrypted user document and its existing ownership/storage contract remain. New/changed facts and summary titles/bodies are instructed to follow the user's question language; dates use TIMEZONE. DEFAULT_LOCALE selects fixed system text; legacy labels and unrelated dates remain readable. Formatting changes are saved only with real changes. Automatic planning shares the existing evaluation budget and cannot invalidate a delivered answer or independently valid summary. Management/history labels remain hidden; natural narration and trace evidence are preserved.

Memory management, past-conversation list/read, and read_file/grep confined to /memories/, /runtime/large_tool_results/, or /runtime/conversation_history/ hide labels even with details ON. General file and Skill labels keep their policy; events/traces remain. Optional narration and result prose are generated by the model.

Trusted sender example
ADMIN_SEND_SYSTEM_NAME=ds_assistant,agent_runtime_admin,KAI_LLM

Trusted CSV trims/removes blank entries and duplicates but preserves exact case and internal text. KAI_LLM differs from kai_llm. _test is neither allowed in the CSV nor stripped for trusted matching; System/Sub registration uses Key binding.

Trusted sender names are not credentials

Trusted senders skip Key and Permission lookup and accept supplied groups. Ingress/API Hub must bind or validate these names for authenticated internal callers; ordinary external users must not choose them freely.

Key registration and lifecycle​

POST a base-name System binding without changing environment or redeploying. POST preserves other active Keys. PATCH changes only valid future expiry of an active Key; inactive returns 409 api_key_not_active. DELETE retains the row and first revocation timestamp. See API Key management.

What execution appears in evidence?​

No separate tool-selection list exists in MCP configuration. Recorded Main/subagent, model, MCP/tool, Skill, guardrail, HITL, and errors appear as semantic evidence. Tool outputs are JSON-safe, and failed observations retain error.message rather than disappearing. Unrecorded provider-private reasoning cannot be reconstructed.

Evaluation is not a graph execution node. Validated responses/failure records stay in ordered run.artifact.output.turn_evaluation. Unconfigured evaluation leaves an empty array; failure records have completion_status="failed", persistence no-op values, and stable failure_reason, without raw exceptions, provider bodies, prompts, or Memory content.

LLM request correlation​

Inbound orch.x_request_id becomes request_id for dedup, Usage, Runs/log/trace. Main, subagents, Evaluator, Deep Search, and compactor can make several provider calls.

Initial/repair Internal LLM calls share Chat-Id but have different Prompt-Msg-Id. Direct MCP Internal LLM calls without chat context may omit Chat-Id but still generate a fresh Prompt-Msg-Id.

Why do x_request_id and Prompt-Msg-Id differ?​

The former identifies one caller request; the latter separates each physical LLM call within it. Never copy the inbound request ID into outbound provider IDs. Chat-Id groups calls belonging to one conversation.

Streaming heartbeat​

SettingRequiredDefaultResponsibility
STREAM_HEARTBEAT_INTERVALNo15Visible idle heartbeat; greater than 0 and at most 55 seconds, below frontend idle timeout.

Request stream defaults to true: true sends SSE and false returns one JSON result from the same execution and content/storage assembly. Detailed progress affects SSE notices only. Main/Subagent internal model streaming and structured Internal LLM non-stream calls remain unchanged. Zero is not a heartbeat OFF value.

Locale controls its fixed wording. Preparation idle carries into streaming and only actual post-filter output resets it. Heartbeat may precede the first answer and stops after terminal/HITL/error/cancellation. Existing correlated logs/traces separate preparation, MCP wait/discovery, compile, first model signal, tool duration, first real visible output, and heartbeat count. Heartbeat is excluded from first real-output timing.

Does HTTP 200 mean streaming succeeded?​

No. Failure after response start has terminal finish_reason=error; HITL has hitl and awaits input. Inspect terminal reason, not just HTTP status or [DONE]. Non-stream Agent failure instead returns HTTP 500 error envelope.

Initial regional installation​

Choose TIMEZONE at first deployment and retain it during operation. Existing Korean services use an unset value or Asia/Seoul with their existing Usage defaults. Usage rows, KST Memory dates, checkpoints, Runs, and conversation summaries are not rewritten; no timezone migration CLI is needed. Other regions use independent new deployments/storage.

The DBA preserves shared standards.usage_log_base types/defaults and other services. Prepare the new child's complete columns, inheritance, constraints, and indexes, then align only that child's created_at default with its region. For an already prepared US West child:

New US West service child default
ALTER TABLE agent_runtime_us_west.agent_runtime_us_west
  ALTER COLUMN created_at SET DEFAULT
  (now() AT TIME ZONE 'America/Los_Angeles');

Deploy with SERVICE_NAME=agent_runtime_us_west and TIMEZONE=America/Los_Angeles. Startup rejects mismatched child defaults without automatically altering tables. Keep existing Korean child defaults as now() AT TIME ZONE 'Asia/Seoul'.

Connections apply the service search path and TIMEZONE. Older connections did not override session timezone; confirm their actual DBA environment with SHOW TimeZone. Aware inputs, timestamptz, and explicit regional conversions preserve instants despite session display changes. API dates use the request application's TIMEZONE and retain explicit offsets' instants.

Naive Usage timestamps store local wall clocks and cannot distinguish the two instants in a repeated DST hour. Use existing timestamptz execution records for precise chronology, ordering, and elapsed analysis. Ambiguous/nonexistent API input requires an explicit offset.

2. Successful streaming Chat​

stream=true; HTTP 200 starts first, and successful terminal delivery establishes completed. Failure after start can still have HTTP 200, so inspect status too. Final loop information is in Chat terminal and Runs detail.

3. Chat waiting for HITL​

Usage is hitl_pending, HTTP 200, no error. A pending row shares the session ID. Resume preserves chat and creates a new request ID. Even after compaction, pending row/checkpoint interrupt—not summary prose—decides resume.

4. Repeated request​

Same scope/request ID does not execute again. The original accepted row stays; a separate duplicate attempt has dedup_result=duplicate, status=rejected, HTTP 409, and a safe duplicate error. Frequent rows may indicate duplicate UI submits or incorrectly reused retry IDs.

5. Invalid identity/UUID​

Missing orch, blank/placeholder user, or nil IDs return 400 invalid_identity; malformed UUID schema returns 422 validation_error. Dots are not validated. Usage is not_applied/rejected with the safe error, without model/RAG/MCP work.

6. Previous stream still active​

Session conflict is rejected, HTTP 409, with dedup_result=accepted or not_applied because the ID may be new. Wait for the previous stream. Duplicate means request-ID collision; conflict means concurrent work in one conversation.

7. Manifest, Probe, Search​

These create no Usage rows. Search X-Request-Id and Probe metadata.x_request_id still correlate responses/logs, but do not identify Chat ledger rows. Repeated Probe payloads both execute workload; there is no separate idempotency store for these APIs.

9. Joining Usage and run summaries​

Native tools are ls, read_file, write_file, edit_file, glob, grep, and subagent task. Writes/edits are allowed only in workspace. No shell/execute. Tool permissions and backend traversal/read-only checks both enforce boundaries. Runtime is not an arbitrary model-created workspace.

Quota measures UTF-8 bytes. Default per-file 512 KiB/thread 2 MiB failures return workspace_quota_exceeded without silently overwriting files. Both settings must be positive and file limit must not exceed total.

Workspace files do not replace delivered answers. The prompt requires results in chat. Runtime conservatively continues once only if the current pass successfully wrote/edited workspace and the answer is empty or save/path-only—not merely because the body mentions a workspace path. Skill reads use [Skill], other filesystem calls [Tool], without changing SSE shape or adding progress when no file work occurs.

The MCP group EXAMPLE_REVIEWERS and the Skill/Agent group ORG_PROCESS illustrate configuration, not mandatory groups. Use actual service policy.

PropertyContract
enabledRuntime activation, default true; false fully excludes it.
includeInManifestRouter inventory visibility, independent of execution.
requestScopedInjectionExplicit body/header destinations for request fields.
timeoutTool-call cap, default 60 seconds; host wrapper for stdio, also adapter connection for HTTP/streamable.
sse_read_timeoutSilence between events after connection, adapter default 300 seconds; optional per-server override.
access.permission_groupsRestricted server group intersection.

Disabled entries remain configuration but disappear from loading, injection, manifest, and execution tracing. Use includeInManifest=false to hide only Router inventory while retaining runtime execution. Evidence retains actual arguments/results, excluding framework input.runtime; nesting identifies the owning Agent.

Access metadata is app-owned and never sent to MCP. Absent/empty access is public; non-empty groups require intersection for exposure and execution.

Injection is separate: it transfers normalized request-body or inbound-header sources into explicit body/header destinations for already permitted tools. All four directions are expressible. Header destinations apply only to HTTP/SSE MCP; write downstream names such as X-User-Id, not snake_case source names. Header comparison is case-insensitive; configuration consistently uses readable hyphenated names.

Does requestScopedInjection grant permissions?​

No. It transfers data during an already authorized invocation; it cannot expose or execute a forbidden MCP. A body injection can supply RAG groups; a header injection can forward correlation metadata.

Stdio call timeout is enforced by Runtime, not an SDK connection argument. HTTP uses it at adapter connection and tool wrapper. Independent per-server discovery budget prevents one slow server from blocking preparation indefinitely. Manifest is partial best-effort; first Chat discovery also isolates failed servers, with no required retriever-name contract.

Chat retains per-server last-known-good definitions. The first request after 600 seconds from completed discovery refreshes registered candidates. Successful servers replace their whole set, including authoritative empty lists. Failed servers retain definitions/state. Changed name/description/schema triggers graph compilation; a candidate is adopted atomically with definitions/state. Failed compile preserves the old graph and advances the completed-attempt clock. Unchanged fingerprints still adopt recovery state. No scheduler/additional TTL/env exists.

Typed connection/session failures count at server scope; per-tool timeout, confirmed stale tool/schema, and backend errors count at tool scope. Two consecutive failures block exposure and dispatch. Invalid arguments, normal empty success, cancellation, and HITL do not count. Classified external failures do not consume global mistake budget, while repeated forbidden calls and execution limits remain. Shared state requires the same connection/authentication scope. Fixed built-in RAG/DS connections retain failures and blocks across requests without resetting on correlation arguments. Custom dynamic request injection retains request-local isolation. Active requests pin definitions and block state; late results cannot poison a newer generation. Adopted discovery success permits new requests; failure keeps blocks until the next 600-second opportunity.

Why can Manifest and Chat have different MCP tools?​

Manifest is static per-server best-effort inventory. Disabled, hidden, or failed servers may be absent while siblings remain. Chat combines currently permitted enabled servers with last-known-good state; an initially failed server is omitted without requiring a particular retriever. Timing, request permissions, and block state can therefore produce different lists. Manifest has no per-user group body, so restricted Skill/Agent descriptions may appear; Chat filters actual exposure again.

Stdio python/python3 resolves to the API's interpreter, so a host virtualenv also runs child MCP with its dependencies. Explicit custom interpreter paths/launchers are retained and must contain required dependencies. sse_read_timeout measures next-event silence, not total execution; default assets use adapter 300 seconds.

note

Manifest visibility follows enabled/includeInManifest/discovery. Per-user runtime visibility follows access.permission_groups independently.
