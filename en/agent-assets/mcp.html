MCP

MCP servers come from assets/mcp_server.json or builtin configuration. If the file exists, an explicitly empty mcpServers is respected rather than replaced with defaults. Without a file, active RAG/DS settings select builtin retriever and ds_retriever candidates. An absent RAG URL disables only builtin search; custom MCPs are independent. RAG-only indices select retriever, DS-only indices select ds_retriever, and both select both, while respecting enabled=false.

Users do not call MCP tools directly. Supply correct Chat orch metadata so the runtime exposes only tools permitted by configuration and authorization.

Builtin servers​

ServerRepresentative toolPurpose
retrievermcp__retriever__rag_searchOrdinary retrieval over RAG indices.
retrievermcp__retriever__deep_searchDeeper search strategies for RAG questions.
ds_retrievermcp__ds_retriever__ds_rag_searchDS index retrieval. Its current asset has includeInManifest=false, so it can be available in Chat while absent from the manifest.

Canonical tool names use mcp__<server_name>__<tool_name>.

Builtin implementations separate server-specific code from shared helpers.

Bundled MCP server layout
app/mcp_servers/
  _common/
    retriever.py
    search_strategy.py
  retriever/
    server.py
    deep_search.py
  ds_retriever/
    server.py

_common/ holds shared RAG gateway, rerank, result-size policy, and strategy descriptions. Deep Search is specific to the RAG retriever and lives in retriever/deep_search.py.

Configuration example​

MCP configuration
{
  "mcpServers": {
    "retriever": {
      "transport": "stdio",
      "command": "python",
      "args": ["-m", "app.mcp_servers.retriever.server"],
      "env": {
        "RAG_API_URL": "${RAG_API_URL}",
        "RAG_API_KEY": "${RAG_API_KEY}",
        "RAG_X_DEP_TICKET": "${RAG_X_DEP_TICKET}",
        "INDEX": "${RAG_INDEX}"
      },
      "requestScopedInjection": {
        "body": [
          {"from": "permission_groups", "to": "permission_groups"},
          {"from": "index", "to": "index", "overwrite": false},
          {"from": "chat_id", "to": "chat_id"},
          {"from": "request_id", "to": "request_id"},
          {"from": "user_id", "to": "user_id"}
        ]
      },
      "enabled": true,
      "includeInManifest": true
    },
    "external_http": {
      "transport": "http",
      "url": "https://mcp.example.com/mcp",
      "requestScopedInjection": {
        "body": [
          {"from": "permission_groups", "to": "permission_groups"},
          {"from": "index", "to": "index", "overwrite": false}
        ],
        "header": [
          {"from": "user_id", "to": "X-User-Id"},
          {"from": "request_id", "to": "X-Request-Id"},
          {"from": "chat_id", "to": "X-Chat-Id"}
        ]
      },
      "enabled": true,
      "includeInManifest": true
    }
  }
}

MCP access​

An entry's access.permission_groups is an exposure allowlist. Missing access or empty groups makes the server public. Otherwise at least one group must overlap with Chat's orch.rag_params.permission_groups before the runtime loads it.

This is application-owned metadata used to filter servers before graph creation, not a payload sent to the MCP endpoint. Unauthorized tools are omitted from the model and rejected by dispatch even if the caller knows their canonical name.

SettingResponsibilityExample
enabledInclude/exclude the server entirely; default true.Set false to disable an MCP.
includeInManifestExpose Router inventory without changing execution availability.Use false for internal-only MCPs.
access.permission_groupsRestrict server/tool visibility.Expose a server only to restricted-team.
requestScopedInjectionPopulate tool arguments (body) or HTTP MCP headers (header).Inject ACLs or correlation IDs.
timeoutTool-call timeout, default 60 seconds and explicitly 60 in builtin assets. Stdio uses a host wrapper; HTTP/streamable also passes it to the adapter connection.Increase only for a server whose normal operation needs longer.
sse_read_timeoutIdle event-read timeout after a streamable/SSE connection opens; adapter default 300 seconds.Set a different event-read limit for a particular server.

enabled=false removes a server from both Chat and manifest. includeInManifest=false preserves Chat availability while hiding only inventory.

Stdio timeout is not passed as an SDK connection argument; Agent Runtime wraps tool execution with it. HTTP/streamable uses it for both adapter connection and tool execution. Separately, MCP_DISCOVERY_TIMEOUT bounds each server's entire discovery. Manifest can return a successful partial inventory excluding slow or failed servers. Initial Chat discovery excludes only failed servers and continues with healthy ones; no specific retriever tool name is required. Temporary failure of a valid external server is distinct from invalid local configuration, which is not silently treated as OFF.

Chat keeps a last-known-good catalog per server. The first request after 600 seconds from the completed discovery attempt checks again. Failed servers retain their catalog; successful servers replace the complete list, including an authoritative empty list. A name, description, or input-schema change requires a new graph. No background refresh occurs without a request. Server entries and access-policy changes require process restart.

Repeated failures and recovery​

SituationBehavior
Two consecutive connection/session failuresBlock all tools from that server.
Two consecutive execution timeouts, structurally confirmed schema mismatches, or backend failures for one toolBlock that tool and retain its siblings.
Invalid arguments, request-specific authentication refusal, successful empty results, cancellation, or HITLDo not count as shared MCP failures.
Successful discovery and adoption after the next 600 secondsGive new requests another opportunity; recovery applies even if the catalog is unchanged.
Failed discovery or failed graph candidate constructionPreserve the adopted graph/state and wait for the next 600 seconds.

Both model exposure and actual dispatch enforce blocks for Main, Subagents, and additional execution. A failure is returned as a Tool result with the matching tool_call_id, allowing the agent to choose another tool or improve its answer. An external tool failure does not automatically stop the entire workflow, and uncertain writes are not automatically replayed. In-flight results are handled, but a late success does not immediately reopen a block.

Requests pin their graph and availability generation. A tool blocked within one request is not reopened midway by another request's recovery. Late results from older generations cannot contaminate new ones. Only matching connection/auth scopes share failures. Fixed built-in RAG/DS connections retain failure counts and blocks across requests; correlation arguments do not reset them. Custom dynamic body/header injection retains request-local isolation. Structurally classified external failures do not spend LoopGuard's global mistake budget; ignored blocks, invalid arguments, and execution limits remain protected.

Failure classification preserves the original remote diagnostic result. Blocked calls return the recorded failure domain/cause without transport or another external failure. Large evidence uses existing offload and bounded reads instead of arbitrary truncation.

Stdio commands python and python3 use the API process's Python executable. Running the API in .venv therefore runs child MCPs there too. Explicit custom commands, absolute paths, and other launchers are preserved.

sse_read_timeout measures inactivity between connection events, not total tool execution time. Builtin assets use the adapter's 300-second default without specifying another value.

Request-scoped injection​

requestScopedInjection is an object with body and header destinations, not an array. A from source can be a normalized Chat body field or an inbound HTTP header, supporting body→body, header→body, body→header, and header→header. Header destinations are supported only for HTTP/SSE transports; stdio/websocket header injection is a configuration error.

SourceExample body[].toExample header[].toMeaning
permission_groupspermission_groupsUnsupported (list)RAG access filter
indexindexX-IndexSearch indices
request_idrequest_idX-Request-IdDownstream correlation
user_iduser_idX-User-IdUser logging/filtering

header[].to is the actual downstream HTTP header name. Map normalized user_id to a hyphenated name such as X-User-Id; snake_case belongs to body sources and destinations. Header names are case-insensitive, so X-User-Id, x-user-id, and X-USER-ID are equivalent. Prefer readable canonical names in configuration.

overwrite: false preserves existing tool arguments or static headers, such as an agent's narrowed index or a fixed authentication header. Header destination matching is case-insensitive.

warning

If the same source occurs in both normalized body and inbound headers, the server rejects the ambiguity rather than choosing precedence. Do not send a user_id header alongside a from: user_id body source. Header destinations accept only scalars: put list-valued permission_groups in body injection and use scalar user_id, chat_id, request_id, or model for headers.

Evidence observation​

No separate setting selects MCP tools for evidence. Executed tools appear as Langfuse tool observations and can be read with JSON-safe input/output, errors, and agent ownership through Runs evidence.

Tool input omits only the top-level framework-injected runtime; real arguments such as query, index, and permissions remain. Embedded tool descriptions/JSON schema in public model input are internal configuration and omitted. Actual Tool result messages and observation outputs remain available.

Evidence request
curl "$AGENT_RUNTIME_API_BASE/v1/runs/run_01J00000000000000000000000/evidence"

Ownership is expressed by nesting: the closest containing type="agent" node owns the tool. Consumers do not need to match separate parent IDs.
