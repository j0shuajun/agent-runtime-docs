Router

Federation Router uses these endpoints to inspect lightweight evidence before selecting a RAG service. They do not execute a full Chat.

GET /v1/manifest​

Return the service's models, indices, description, example queries, and public capabilities.

Request
curl "$AGENT_RUNTIME_API_BASE/v1/manifest"
Response
{
  "metadata": {
    "timestamp": "2026-07-14T10:10:00+09:00",
    "request_id": "6ebdc6ee-134e-4b1a-a7cc-20379508395d"
  },
  "service": {
    "name": "Agent_Runtime",
    "model_names": ["<model-id-from-catalog>"],
    "index": "rag-index"
  },
  "model_card": {
    "description": "## Overview of Agent Runtime\n...",
    "example_queries": ["Find and summarize exceptions to this policy in connected documents."]
  },
  "capabilities": {
    "tools": [{"id": "tool-1", "name": "mcp__retriever__rag_search", "description": "..."}],
    "agents": [{"id": "agent-1", "name": "example-agent", "description": "..."}],
    "skills": [{"id": "skill-1", "name": "example-skill", "description": "..."}]
  }
}

capabilities.tools comes from MCP tool discovery. Servers with enabled=false are excluded from the runtime and manifest. Servers with includeInManifest=false may remain available in Chat but are omitted from manifest capabilities. capabilities.agents and capabilities.skills come from asset descriptions.

Manifest discovery is best effort per server. A timeout or error can produce a successful partial inventory that excludes only the failed server's tools. Capabilities vary with active assets and discovery state; the JSON above illustrates the response shape.

Server-written descriptions, examples, and notices follow DEFAULT_LOCALE; timestamp offsets follow TIMEZONE. Search guidance reflects tools that were actually discovered and made public. External tool descriptions and machine-readable fields are not automatically translated.

POST /v1/probe​

Retrieve RAG evidence for the Router's search_query. This endpoint does not execute the agent loop, HITL, or session memory.

Request
curl "$AGENT_RUNTIME_API_BASE/v1/probe" \
  -H "Content-Type: application/json" \
  -d '{
    "metadata": {
      "chat_id": "afe26351-e2e5-4c70-8f4d-2a52f5dac7ac",
      "x_request_id": "6393d0c9-18ff-48b4-9f42-6cb687509587",
      "user_id": "employee.one",
      "permission_groups": ["example-team"]
    },
    "context": {
      "original_query": "What is a deployment delay?",
      "search_query": "deployment delay causes",
      "is_multi_turn": false,
      "keywords": ["deployment", "delay"]
    },
    "rag_options": {
      "max_results": 5
    }
  }'
Response
{
  "metadata": {
    "timestamp": "2026-07-14T10:11:00+09:00",
    "chat_id": "afe26351-e2e5-4c70-8f4d-2a52f5dac7ac",
    "x_request_id": "6393d0c9-18ff-48b4-9f42-6cb687509587",
    "user_id": "employee.one",
    "permission_groups": ["example-team"],
    "original_query": "What is a deployment delay?",
    "search_query": "deployment delay causes"
  },
  "evidence": {
    "rag": {
      "status": "ok",
      "results": [
        {
          "id": "rag-1",
          "title": "Deployment Delay Overview",
          "content": "Deployment delay can occur when ..."
        }
      ]
    }
  }
}

metadata.chat_id and metadata.x_request_id must be UUIDs. Probe creates no Chat usage-ledger row and has no persistent dedup store. Repeating the same user_id:chat_id:x_request_id therefore executes both RAG workloads.

Probe strictly rejects unknown fields. context can include optional conversation_summary, topic, and intent; rag_options.max_results ranges from 1 to 20. The server uses the Router's search_query unchanged and calls retrieve-cc over all configured RAG indices.

RAG and rerank share one PROBE_TIMEOUT budget. On rerank failure or budget exhaustion, preserve the original RAG order. An absent builtin RAG URL or public RAG index returns 404 feature_disabled. A successful active RAG response with no hits produces evidence.rag.status="empty". Probe safely projects only title/content; upstream scores, URLs, and document IDs are omitted.
