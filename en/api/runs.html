Runs

Evidence preserves execution results while excluding fixed internal settings. Runs is an operator/debugging API for status, loop telemetry, Main/subagent structure, and exact observation inputs/outputs. It is not a user answer replay API.

tip

Start with POST /v1/runs to find a run_id, then fetch detail and evidence. If you know request_id, filter Usage first and then inspect the run summary.

POST /v1/runs​

Lists a user's run summaries by deployment-zone time range and cursor. The list does not include full answers, provider traces, or retrieved document bodies.

FieldMeaning
user_idRequired user identity; retrieves that user's newest limit runs.
fromStart time. Accepts dates, minute/second datetimes, ISO T, Z, and offsets. Naive values use TIMEZONE.
toEnd time with the same formats; explicit offsets retain their meaning.
limit1–100, default 20.
cursorNext-page token; resend exactly as provided.
Request
curl "$AGENT_RUNTIME_API_BASE/v1/runs" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "employee.one",
    "from": "2026-07-14",
    "to": "2026-07-15",
    "limit": 20
  }'
Response
{
  "items": [
    {
      "run_id": "run_01J00000000000000000000000",
      "user_id": "employee.one",
      "chat_id": "2b0e1c88-540d-4af7-85d8-b1e7f6fa865e",
      "request_id": "896cd7ad-8e3c-4c85-b918-a294d133c44e",
      "created_at": "2026-07-14T10:12:00+09:00",
      "status": "completed",
      "model": "<model-id-from-catalog>",
      "stream": true,
      "interaction_id": null,
      "parent_run_id": null,
      "phase_index": 0
    }
  ],
  "query": {"user_id": "employee.one", "from": "2026-07-14", "to": "2026-07-15"},
  "page": {"limit": 20, "returned": 1, "has_more": false, "next_cursor": null}
}

The database filters by user_id before ordering created_at DESC, run_id DESC and limiting results. It does not fetch global recent runs and then filter the user.

HITL fieldMeaning
interaction_idnull for ordinary runs; initial HITL uses its own run_id, and resumes use that initial ID.
parent_run_idnull initially; previous phase's run ID on resume.
phase_indexStarts at 0 and increases with each resume.

Naive range values use TIMEZONE. With default Asia/Seoul, from: "2026-07-14" starts at midnight, and to: "2026-07-15" includes that entire day. to: "2026-07-14 10:30" includes that minute. Day boundaries account for the zone's DST. Ambiguous/nonexistent datetimes require an offset. Response timestamps use the deployment zone's offset.

Next-page cursor​

When page.has_more=true, the response includes page.next_cursor. Preserve user_id, from, to, and limit; add only cursor for the next page.

  "page": {
    "limit": 2,
    "returned": 2,
    "has_more": true,
    "next_cursor": "eyJ2IjoxLCJxIjoi..."
  }
}
Next page request
curl "$AGENT_RUNTIME_API_BASE/v1/runs" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "employee.one",
    "from": "2026-07-14",
    "to": "2026-07-15",
    "limit": 2,

  }'
Next page response excerpt
{
  "items": [
    {"run_id": "run_01J00000000000000000000000"}
  ],
  "query": {"user_id": "employee.one", "from": "2026-07-14", "to": "2026-07-15"},

}
warning

Do not interpret or modify cursors. Changing any query field while reusing one returns 422. Restart from the first page without a cursor when changing filters.

GET /v1/runs/{run_id}​

Returns one run summary, loop telemetry, and the Main/subagent execution tree.

Request
curl "$AGENT_RUNTIME_API_BASE/v1/runs/run_01J00000000000000000000000"
Response
{
  "run": {
    "chat_id": "2b0e1c88-540d-4af7-85d8-b1e7f6fa865e",
    "request_id": "896cd7ad-8e3c-4c85-b918-a294d133c44e",
    "created_at": "2026-07-14T10:12:00+09:00",
    "status": "completed",
    "model": "<model-id-from-catalog>",
    "stream": true,
    "interaction_id": null,
    "parent_run_id": null,
    "phase_index": 0
  },
  "loop": {
    "tool_calls": 2,
    "model_calls": 3,
    "stop_reason": "completed",
    "duration_ms": 12400,
    "repeats_blocked": 0,
    "compaction": {
      "occurred": true,
      "count": 1,
      "cutoff_index": 37
    }
  },
  "execution_summary": [
    {
      "type": "agent",
      "name": "main",
      "observations": [
        {"type": "model", "name": "main"},
        {"type": "tool", "name": "rag_search"},
        {"type": "skill", "name": "policy-research"},
        {
          "type": "agent",
          "name": "researcher",
          "observations": [
            {"type": "model", "name": "researcher"},
            {"type": "tool", "name": "deep_search"},
            {"type": "model", "name": "researcher"}
          ]
        },
        {"type": "model", "name": "main"}
      ]
    }
  ],
  "links": {
    "self": "/v1/runs/run_01J00000000000000000000000",
    "evidence": "/v1/runs/run_01J00000000000000000000000/evidence"
  }
}

run comes from PostgreSQL, loop from that run's Langfuse run.artifact, and execution_summary from semantic observations. Public detail excludes user_id and model/tool inputs/outputs. Discover a user's runs using the PostgreSQL-backed list, then fetch the selected ID's detail/evidence.

The root is the Main Agent; its observations preserve execution order. A sequence glob → ls → glob appears in that order. Each subagent call becomes one nested type="agent" node at its execution position, so repeated calls to the same named Agent are separate nodes. Evidence contains actual inputs and outputs.

LocationInterpretation
run.statuscompleted, hitl, or failed in detail. running appears only in list; detail is not yet available.
loop.tool_callsFramework tool invocation count.
loop.model_callsModel calls, including continuations/retries.
loop.repeats_blockedRepeated tool calls blocked.
loop.compactionNative compaction in this request: occurred, actual count, and latest cutoff_index.
execution_summaryAgent ownership and ordered model/tool/Skill execution without inputs/outputs.

List and evidence contain no loop. Compaction metadata appears only in Chat terminal/non-stream responses and Runs detail. Its count is actual native compaction occurrences. After a completed cycle and meaningful Main work, Chat can announce another compaction in the same request. Immediate retriggers without work suppress duplicate notices without reducing the count.

Overflow remaining after forced compaction has stop_reason=context_overflow. Native summary bodies, archive paths under /runtime/conversation_history/**, and raw history remain private trace/state and are excluded from public Runs/evidence.

Raw tool_calls can include subagent task and Skill read_file. Semantic projection represents those as agent and skill, so counting public tool nodes need not equal the raw counter.

Older artifacts missing the entire loop.compaction key receive {"occurred": false, "count": 0, "cutoff_index": null}. An existing malformed object with missing count or private fields such as summary_text/file_path fails public projection rather than being silently repaired.

GET /v1/runs/{run_id}/evidence​

Returns Langfuse semantic Main/subagent, model, tool, and Skill observations. It does not expose live evidence before a run becomes terminal.

Request
curl "$AGENT_RUNTIME_API_BASE/v1/runs/run_01J00000000000000000000000/evidence"
Response
{
  "run_id": "run_01J00000000000000000000000",
  "observations": [
    {
      "type": "agent",
      "name": "main",
      "observations": [
        {
          "type": "model",
          "name": "main",
          "input": {"messages": [{"role": "user", "content": "Investigate deployment delays."}]}
        },
        {
          "type": "tool",
          "name": "rag_search",
          "input": {"query": "causes of deployment delays"},
          "output": {"results": [{"title": "Deployment Delay Overview", "score": 0.82}]}
        },
        {
          "type": "agent",
          "name": "researcher",
          "observations": [
            {
              "type": "model",
              "name": "researcher",
              "input": {"messages": [{"role": "system", "content": "Review the causes independently."}]}
            },
            {
              "type": "tool",
              "name": "deep_search",
              "input": {"query": "deployment delay verification"},
              "output": {"results": [{"title": "Verification", "score": 0.91}]}
            },
            {
              "type": "model",
              "name": "researcher",
              "output": "Here are the research findings."
            }
          ]
        },
        {
          "type": "model",
          "name": "main",
          "output": "Here is the final answer."
        }
      ]
    }
  ],
  "page": {"returned": 8, "complete": true, "next_cursor": null},
  "links": {
    "self": "/v1/runs/run_01J00000000000000000000000/evidence",
    "run": "/v1/runs/run_01J00000000000000000000000",
    "next": null
  }
}
LocationInterpretation
observations[]Main-rooted tree with owned execution and subagents in order.
type="model" / nameOne LLM invocation and its owning Agent; name is not the provider model ID.
input / outputSanitized JSON-safe values without arbitrary previews or resummarization. Only fixed internal settings are excluded; no per-observation detail calls are needed.
error{ "message": "..." } only for failed observations. Successful nodes do not repeat status fields.
pageNewly returned observation count, completion, and next cursor.

Pagination is automatic by JSON size, with a 4 MiB soft page budget. Observations are never split. If adding the next one exceeds the budget, the response includes page.complete=false, page.next_cursor, and links.next; follow that link unchanged. Required Agent ancestors repeat on later pages, while page.returned counts only newly returned observations. An observation larger than 4 MiB is returned whole on its own page: a 12 MiB Tool result retains its middle and ending. The cursor continues from the following observation. There is no separate single-observation rejection limit. Large JSON supports HTTP gzip.

Availability and errors​

SituationDetail/evidenceMeaning
No PostgreSQL run ID404 run not foundRun does not exist.
Summary still running409 run_not_terminalTerminal artifact is unavailable.
Terminal artifact not visibleRetries within configured deadline, then 503 observability unavailableLangfuse delay or write failure.
Terminal summary and artifact ready200Detail/evidence can be read.

Each HTTP request creates one LangGraph trace in Langfuse Sessions. A HITL question and each resume have distinct run_id traces, each with one run.artifact child. interaction_id, parent_run_id, and phase_index connect phases. Session turns remain oldest-first. Reads use the whole LANGFUSE_RUN_READ_TIMEOUT deadline; large evidence does not fail prematurely after an arbitrary fixed retry count.

Delegation and compaction positions​

A Subagent Agent node's input contains actual task args and output contains the actual return delivered to Main. An explicitly supplied fork_turns is retained; omitted values are not invented. Internal Model/Tool activity stays nested in execution order. Native namespaces distinguish parallel invocations even when Agent names match.

Evidence timeline excerpt
[
  {
    "type": "agent",
    "name": "evidence-reviewer",
    "input": {"subagent_type": "evidence-reviewer", "description": "Review evidence", "fork_turns": "2"},
    "output": "Confirmed the corrected value 17.25.",
    "observations": [{"type": "model", "name": "evidence-reviewer"}]
  },
  {"type": "compaction", "name": "compaction", "output": {"result": "applied"}},
  {"type": "model", "name": "main"}
]

Compaction appears at its actual position inside the owning Agent, with applied or fallback outcome. Summary bodies, inherited summaries, and internal summary Generations remain private. Detail's execution_summary includes the same positioned type without I/O. Overall response structure and observation-level pagination remain.

Agent I/O appears once on the page selecting that Agent as a new observation, not repeatedly on later ancestor scaffolds. Raw Langfuse traces remain unchanged. Reads page all existing semantic markers and use Native namespace ownership, avoiding repeated giant framework state copies. If complete relationships cannot be established within the deadline, return 503 rather than partial evidence.

Checkpoint collection leaves RunIndex and Langfuse intact, so recorded Runs remain readable. run.artifact.run.is_routed records the actual HTTP execution's routing boolean, including each HITL resume's own request value; it is not a public Runs field. Under the existing cancellation contract, a RunIndex left running still returns 409 for detail/evidence and is protected from collection. Elapsed time alone does not invent terminal state.
