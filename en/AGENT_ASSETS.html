Agent Assets

Agent Runtime's Chat endpoint constructs a DeepAgents runtime using each request's identity, permission groups, and indices. It uses only permitted MCP tools, Skills, and Agents.

Agent assets extend Main's capabilities. Users do not select or call them directly; the runtime exposes relevant assets using /v1/chat/completions orch metadata and service settings.

Execution flow​

Asset types​

AssetRoleReference
MCPServers/tools for retrieval, deep search, and external execution.MCP
SkillsInstruction bundles for working methods or review criteria.Skills
AgentsSubagent definitions for focused review/analysis.Agents

Agent-visible virtual filesystem​

Operators put physical assets in assets/skills/ and assets/agents/. Agents see virtual roots tailored to the request's owner and permissions, rather than host paths.

Agent-visible pathContentAccess and lifetime
/workspaceDrafts, intermediate analysis, and shared Main/Subagent working filesRead/write/edit only within the current user_id:chat_id thread, persisted in PostgreSQL checkpoints.
/runtimeNative conversation archives and framework-owned artifactsThread-private and checkpoint-backed. Only the framework writes. Models can read exact conversation-provided paths under /runtime/conversation_history/<artifact> or /runtime/large_tool_results/<artifact>.
/memoriesThe current user_id's /memories/MEMORY.mdUser-scoped and read-only when personalization is ON. OFF blocks automatic loading, prompt injection, and ordinary file reads.
/skillsPermitted physical assets/skills definitionsRead-only.
/agentsPermitted physical assets/agents definitionsRead-only.

For example, user A's /workspace/notes.md in chat 1 remains readable by later requests in that chat and another API process, but not by A's chat 2 or user B. The pod's physical /, assets/mcp_server.json, and other host files are not mounted. Shell/execute is unavailable. Agents cannot modify /memories, /skills, or /agents. /runtime is separate from workspace quotas and is not a general working directory. Its root, arbitrary namespaces, relative paths, and traversal are not readable.

Agents use ls, glob, grep, read_file, write_file, and edit_file as needed. Reading a Skill produces [Skill] progress; other filesystem work produces [Tool] <tool>. Workspace files are internal working material: the Agent must deliver the requested result in the final chat body, rather than merely naming a path.

Hiding detailed progress preserves execution and permission checks. Personalization OFF retains existing Memory, conversation history, and past-conversation lookup. Users can explicitly delete Memory through Main's dedicated tool, which does not delete conversation history, summaries, or checkpoints.

Request context​

Chat orch metadata becomes request-scoped runtime context.

Request-scoped context
{
  "orch": {
    "chat_id": "2b0e1c88-540d-4af7-85d8-b1e7f6fa865e",
    "x_request_id": "896cd7ad-8e3c-4c85-b918-a294d133c44e",
    "identity": {
      "user_id": "employee.one",
      "send_system_name": "ds_assistant"
    },
    "rag_params": {
      "index": "rag-index",
      "permission_groups": ["example-team"]
    }
  }
}
ValueInternal use
user_idSession isolation, usage logging, and MCP body/header injection.
identity.send_system_nameWith auth ON, distinguishes exact trusted sender passthrough, System/base _test binding, and personal callers using omitted/blank/exact api. OFF skips those branches while retaining identity and ownership.
chat_idConversation thread, HITL resume, and dedup scope.
x_request_idCaller-provided dedup/correlation ID, normalized to request_id for MCP/RAG tracking.
rag_params.indexRAG retrieval index selection.
rag_params.permission_groupsResolved MCP, Skill, Agent visibility and RAG access filtering.

Effects of permission groups​

Different permission_groups can expose different capabilities for the same question.

TargetFiltering
MCP serverIts access.permission_groups checks the request groups.
SkillSKILL.md frontmatter access.permission_groups applies.
AgentAgent Markdown frontmatter access.permission_groups applies.
Virtual filesystemOnly permitted Skills/Agents appear under /skills and /agents. /workspace and framework-owned /runtime are thread-isolated.
RAG retrievalInjected MCP permission_groups become the RAG filter.
Runs evidenceLangfuse observations expose full execution inputs/outputs in Main/Subagent nesting. Fixed internal settings are excluded: Main system/developer messages, tool descriptions/schema, tool runtime, framework metadata, private provider reasoning, and internal IDs. Subagent system prompts remain available.

Empty permission groups may reduce both retrieval results and internal capabilities.

MCP requestScopedInjection is independent of authorization. It maps normalized body fields and inbound headers into tool arguments (body) or HTTP MCP headers (header).

Manifest capabilities​

GET /v1/manifest exposes MCP tools, Skills, and Agents so a Router can understand the service. It is a static inventory without a per-user permission body. Per-request visibility based on access.permission_groups is determined by Chat.

Restricted Skill/Agent names and descriptions may therefore appear in the manifest. It is not a metadata security boundary. Do not put credentials, sensitive internal information, or permission-protected content in descriptions.

Caller boundaries​

RecommendedAvoid
Generate stable orch.identity.user_id, chat_id, and x_request_id.Reusing a request ID for a different user request.
Supply the appropriate sender and active binding key when auth is ON.Using a System key as a personal key, or claiming System identity with a personal key.
Render hitl as a user question.Discarding the interrupted chat_id and starting a new chat.
Read /v1/manifest to understand service scope.Directly invoking MCP tools, Skill files, or Agents.
Read operational evidence through /v1/runs*.Expecting raw provider traces or private reasoning in API responses.

MCP tools, Skills, Main/Subagents, and model calls are recorded as Langfuse observations. Inspect each observation's input/output and its containing agent node in Runs evidence to identify execution ownership. Public responses remove framework metadata/internal IDs and express ownership through nesting.

Turn Evaluation is not an Agent execution observation and is excluded from evidence. It remains in terminal Langfuse run.artifact.output.turn_evaluation. An empty array means it did not execute; a failed evaluation leaves a record with completion_status="failed" and a safe failure_reason.

enabled=false excludes an MCP from both runtime and manifest. includeInManifest=false retains Chat availability but hides Router inventory.
